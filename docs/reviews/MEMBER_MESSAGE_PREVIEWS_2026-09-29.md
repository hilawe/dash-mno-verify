# Member message previews and checks

Generated from revision `00f292c` with synthetic identifiers and a simulated September 29, 2026,
noon New York challenge. These are exact source-generated text captures, not screenshots from live
platform accounts. No messages were sent and no real credentials were used. Network replies and
platform operations were replaced with fixtures. Matrix room privacy was assumed for the formatting
probe, so this capture is not evidence that its privacy guard works.

The Discord reply was generated by its exported message functions. Telegram and Matrix message
handlers and the web request handler were executed with mocked dependencies. The test also invoked
Telegram's actual `/verify` handler with `chat.type = supergroup`. It made a gateway request and posted

## Recommended message changes

These are recommendations, not changes to the captured runtime output.

- Replace the absolute privacy sentence with “The proof hides your voting key and which masternode
  you control. Use a separate computer and network to avoid exposing the node through your connection.”
- Put the first-time setup link before terminal commands. Let returning members skip directly to the
  fresh challenge and proof step.
- Say “After registration, request `/verify` again and use that new challenge.” Do not make users
  reason about whether their earlier challenge survived downloading software and keys.
- Distinguish “voting-key control” from “running a node,” since voting delegates may qualify.
- Give Telegram a private-chat guard, code-formatted commands, challenge deadline, and plain refusal
  explanations. Its actual submission is a document upload, not Discord's `/submit`.
- Give configuration failures such as `engine-mismatch` an administrator action instead of an
  invitation to generate the same doomed proof again.
- Replace “re-verify before then to keep access” with instructions that explain renewal at fixed
  boundaries. An early proof does not extend a grant into the next season.

For the small live pilot, inspect desktop and mobile output with an ordinary member account, check
that every command copies as a single command, and verify that the challenge attachment accompanies
the intended message if it splits. No live Discord, Telegram, or Matrix rendering was tested here.

Sources for platform limits are the [Discord message reference](https://github.com/discord/discord-api-docs/blob/main/developers/resources/message.mdx)
and [Telegram Bot API](https://core.telegram.org/bots/api#senddocument), where API means application
programming interface. The raw capture and the probe that produced it were delivered with the review, not in this
repository.
